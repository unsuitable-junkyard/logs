## convert.py（二段目）

処理は上から順にこう並んでる。

1. キーワードリンクを中身だけ残して除去
2. ランキングバナー除去
3. `svg` `button` `colgroup` を丸ごと除去
4. 属性を許可リスト方式で掃除（`a` は href/target、`img` は src/alt/width/height など。許可リスト外は全部捨てる）
5. 属性なしspanを剥がす
6. 枠のstyleをクラスに置換
7. 空段落除去、`<br />`→`<br>`、`<hr />`→`<hr>`
8. 見出しレベルの付け替え（`HEADING_MAP`）
9. ラベル検出
10. 連続hrの統合

**ラベル検出の3形態**
- 単独行（`<p>ラベル</p>` と見出し）
- br続き（`ラベル<br>本文`）
- コロン直結（`あなた：本文`）

見出しは、h5またはコロン付きだけをラベル扱いにする。コロンなしのh1〜h4で同名なら「本文の見出し」と見なして触らない（レポートでは3件）。

**組み立て（assemble）**
- 各ラベルの前に `<br>` と `<hr>` を入れる
- ユーザー側は `.you` の枠。枠なしなら、次がAIラベルのときだけ包む
- AI側は枠なしでラベルを太字で付ける

**設定（先頭にまとまってる）**
`HEADING_MAP` / `WRAP_UNBOXED_USER` / `INLINE_LABELS` / `DROP_BADGES`（既定は4oバッジを残す）/ `WHO`（ホワイトリスト）/ `BOX_KEYS` / `RARE_TAGS` / `CSS`

**出力**
- `html\日付_タイトル.html`。`BASENAME / DATE / STATUS / CATEGORY` は `<body>` 先頭のコメントに退避
- 下書きは `html\_draft\`
- 同名衝突は `_2` `_3`
- 無題はTITLEが空なら本文先頭の見出しから「仮タイトル：」を剥がして代用
- ファイル名はタイトルを80文字で切る

## 原因は「`<p><strong>ユーザー</strong><br />…`」を `.you` と認識したこと

1. `ユーザー` → `👤You:` に変換され、**枠なしユーザー発言**として扱われる
2. 次のラベルを探すと、台本の `ChatGPT（ナレーション調）` は割れた `<strong>` と補足付きで**未検出**

DIV_OPEN_TOK = re.compile(r"<div(\s[^>]*)?>|</div>", re.I)

**2. 関数を追加（`convert_boxes` の下あたり）**

```python
def convert_bare_divs(s: str, S: Counter) -> str:
    """属性なし<div>を整理する。
    中にブロック要素がなければ <p> に変換、あれば開閉タグごと剥がす。
    class付きの枠(.you等)は触らず、対応が取れない孤立タグもそのまま残す。"""
    stack, edits = [], []
    for m in DIV_OPEN_TOK.finditer(s):
        if m.group(0).startswith("</"):
            if stack:
                o_start, o_end, bare = stack.pop()
                if bare:
                    inner = s[o_end:m.start()]
                    if BLOCK_CHILD_RE.search(inner):
                        edits += [(o_start, o_end, ""), (m.start(), m.end(), "")]
                        S["属性なし<div>を剥がし(中にブロックあり)"] += 1
                    else:
                        edits += [(o_start, o_end, "<p>"), (m.start(), m.end(), "</p>")]
                        S["属性なし<div>を<p>に変換"] += 1
        else:
            stack.append((m.start(), m.end(), not (m.group(1) and m.group(1).strip())))
    if not edits:
        return s
    out, pos = [], 0
    for a, b, rep in sorted(edits):
        out.append(s[pos:a])
        out.append(rep)
        pos = b
    out.append(s[pos:])
    return "".join(out)
```

| 末尾にゴミ(`あなた:` と番号付きの行) | 剥がされた見出し40個が末尾にまとめて出力された |
| 記号や空白が微妙に違う | 変換時の正規化。内容への影響は小さい |

**修復の方針**
1. **末尾の塊を切る。** 末尾の `あなた:` から始まる見出し群を切り落とす。上の照合どおり、あの塊は見出しの寄せ集めなので、情報は失わない。
2. **ユーザー発言にラベルを戻す。** `ChatGPT` ラベルの返答のあと、空行を挟んで次に来る塊を、ユーザー発言として `👤You:` を付ける。AI 側のラベルが残っているのが手がかりになる。
3. **例外を拾う。** 見出し群の中の番号付き行は、ChatGPT の返答の章題だった可能性がある。末尾の塊と本文を突き合わせれば、元の位置に戻せる可能性もある。ただし戻せないものは、そのまま捨てる方針で十分だと思う。

この「ラベル再挿入と末尾除去」を `convert.py` の前段に置けば、`WHO` のラベル判定や枠・`<hr>` のロジックはそのまま使える。Git 側の約7,500本を HTML にする時の入口は、これで済む見込みだ。

次の作業には、Git 側のフォルダの場所、拡張子、本数が必要になる。それに加えて、ラベルが落ちている記事が odt 由来のこの型だけなのか、別の型の壊れ方もあるのかを見たい。壊れ方が違うものは、数本サンプルをもらえれば型を分類する。
