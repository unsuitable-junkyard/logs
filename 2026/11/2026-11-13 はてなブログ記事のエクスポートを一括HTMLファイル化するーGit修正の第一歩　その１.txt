## なぜ二段が強いか

最大の理由は、**変換ルールは絶対に一発で決まらない**こと。68万行のゴミパターンは、走らせてから「なんやこのタグ」と発見するもんや。分割済みの `raw/` を残しておけば、変換だけ何度でもやり直せる。一段で全部やると、毎回68万行を舐め直す羽目になる。

## 一段目（分割）の注意点

- 記事区切りは `--------`（ハイフン8個）**単独行**、フィールド間の `-----`（5個）とは別物。行全体の完全一致で判定すること。
- AIログ本文に罫線で `-----` が混ざる可能性があるので、念のため「区切りの次の行が `AUTHOR:`」まで確認すると安全。
- ヘッダ（TITLE / BASENAME / DATE）は分割時に辞書として抜いておくと、二段目が楽になる。

```python
import re
from pathlib import Path

text = Path("export.txt").read_text(encoding="utf-8")
posts = re.split(r"\n--------\n(?=AUTHOR:)", text)
```

6,400本ならメモリに全載せで余裕。ここは気負わなくていい。

## 二段目（変換）の落とし穴

**1. 話者ラベルの誤爆が一番怖い**
サンプルにも「あなたはどのような神について〜」という本文があるやろ。「あなた」で始まる行を雑に拾うと、普通の文が👤You:に化ける。判定は「`<p>` 直後がラベルのみ＋`<br />`」「コロン付き」のように**形を限定**するのが安全。

**2. 表記ゆれは先に集計する**
いきなり置換せず、まず `<p>` 直後〜`<br />` までの文字列を全記事から抜いて頻度表にする。ここで「自分」「Copilot」「Gemini」「Chat GPT」「ChatGPT」あたりの全パターンが見える。サンプルが「自分」始まりな時点で、指定リストにない表記が他にもゴロゴロいるはず。ここは二段方式の旨みが出る部分。

**3. はてなキーワードリンクは除去対象の筆頭**
`<a class="keyword" href="...">神道</a>` は、中身のテキストだけ残して `<a>` を剥がす。これはサンプルだけで山ほどあるし、本文は変えずに装飾だけ消せるので安全。

**4. `<blockquote>` の扱いを先に決める**
サンプルでは、AI発言が `<blockquote>` に入っとる。「👤You:」を枠で囲む新方式に統一するなら、blockquoteは外すのか残すのか。ここを決めずに走ると、枠とインデントが二重になる。

**5. 空段落 `<p> </p>`**
サンプルは全段落の間に挟まってる。除去して、会話の切り替わりだけ `<br>` で空ける形でいい。

## チェックは「目視」じゃなく自動で

6,400本を目視は無理。愛を込めて言うけど、それは「やる」と言った人間が大体途中で諦める。自動検証をこう組むといい。

- 変換前後で**タグを全部剥がしたテキストの文字数**を比較（話者ラベルや `<hr>` 分の差は許容）。本文の欠落や誤削除を機械的に検知できる
- `<hr>` の数と話者ラベルの数が一致しているか
- 想定外のラベル候補（`<p>` 直後の短い文字列＋`<br />`）が残っていないか → ログに吐く
- 異常値の記事だけ抜き出して、数本だけ目視

## ファイル名の罠

- `/ ? : * " < > |` などはタイトルから除去か置換。「※約３万字」の全角記号はOKやけど、長いタイトルはパス長制限に注意
- 1日6〜14本ペースやと、**日付＋タイトルが衝突する日**が必ず出る。衝突時だけ連番を付ける保険を入れておくこと（時刻は不要という指定は守りつつ）

## 一個だけ見落としそうな点

ブログ方針が「生ログで基本修正しない」やろ。ところがサンプルの末尾には「ソース: Copilot との会話」「神 - Wikipedia」みたいな**Copilot出力由来の出典行**が入っとる。これが「ゴミ」なのか「ログの一部」なのか、境界を決めずに走ると、後で「消すつもりなかった行が消えた」が起きる。HTMLの飾りは消す、**テキスト内容は消さない**を原則にしといたら、チェックの文字数比較とも噛み合って筋が通る。

見出しは「h1〜h4を全部h3に統一」の解釈で組むのが自然やと思うけど、これは階層が潰れるので、長い記事で小見出しが多い回は読みにくくなるかもしれん。まあ、そこは後で気になったらルールを1行直せばええ（二段方式やし）。

## 設計のポイント

- **記事境界の判定**：`--------` が単独行 **かつ** 次の行が `AUTHOR:` のときだけ切る。本文中の罫線で誤爆せん。
- **無加工で保存**：改行コード（CRLF）もそのまま保持。ここでは一切変換しない。「HTMLの飾りは二段目で消す」という方針と噛み合う。
- **ファイル名**：`00001_2024_10_14_101500.txt` 形式（通し番号＋BASENAME）。1日に何本出しても衝突せん。「日付＋タイトル」への命名は二段目でやる前提やから、ここは衝突回避と順序保持を優先した。
- **自動チェック**：`logs\report.txt` に以下が出る。
  - 総行数と、書き出し行数＋区切り行の突き合わせ（行の取りこぼし検知）
  - BASENAME / TITLE / BODY 欠落、BASENAME重複の一覧
  - STATUS内訳（Publish と Draft が混ざってるか分かる）
- **index.csv**：no / file / basename / date / title / status / category / 行数 / 文字数。Excelでそのまま開ける（BOM付きUTF-8）。二段目はこの一覧を読んで回せる。
