## 何が起きる話か

Markdownには「改行1個は改行として扱わず、前の行とくっつける」っていうルールがある。段落を分けたいときは空行を入れる決まりや。

Geminiの回答はこんな形になってる。

```
課題と今後の展望
財源の確保: 大規模な…
インフラ整備: 新しい…
```

これを普通のMarkdownレンダラ（GitHubのプレビューやPythonのmarkdownライブラリ）に通すと、こう表示される。

```
課題と今後の展望 財源の確保: 大規模な… インフラ整備: 新しい…
```

全部が1段落にまとまって、壁みたいになる。

## 影響が出るところ、出ないところ

- **txtにするとき**：影響なし。改行はそのまま残る。
- **自作のtxt2html.pyみたいに1行ずつ`<p>`や`<br>`にする方式**：影響なし。
- **市販のMarkdownライブラリに丸投げする方式**：ここだけくっつく。

元のMDは「生ログの正本」やから、そこに空行を足して回るのは筋が違う。直すなら変換する側や。

## 変換側で直す方法（将来用のメモ）

一番簡単なのは「改行1個も`<br>`にする」設定を入れることや。PythonのmarkdownライブラリやったらこれだけでOK。

```python
markdown.markdown(text, extensions=["nl2br"])
```

自前で変換するなら、行ごとに`<br>`を付けるだけでも済む。

## 課題メモ（コピペ用）

```
【MD→HTML変換時の課題】
Gemini等のログは改行1個で見出し・箇条書きが続いている。
標準Markdownレンダラだと段落が連結されるので、
変換時に nl2br（改行→<br>）相当の処理を入れること。
元MDは修正しない。
```

この件はHTML化に手を付けるときに思い出せば間に合う。今は5427行の「Gemini:」→「あなた：」だけ直せば、このログはほぼ完成や。
